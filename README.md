# 결핍 이론 실습실 (12·13주차)

지난해 RPM 원본의 6개 행렬/선택지/정답과 하트·꽃 20회 시행 규칙을 유지한 **별도 Streamlit 앱**입니다. BQ(retire) 코드와 데이터는 수정하지 않습니다.

## 학생용
- 교수자가 여는 분반만 입장 가능. 이름(또는 동일한 별명)으로 식별합니다.
- 12주차 RPM: 6문항 × 6개 보기, 정답 `4,2,1,4,2,1`.
- 13주차 하트/꽃: 총 20회, 자극 및 위치는 시행마다 독립 무작위.
- 각 문항의 반응시간은 **휴대전화 브라우저의 `performance.now()`**로 측정합니다.
- 마지막 시행 후 Streamlit 서버에 전송하여 Supabase에 저장 성공한 경우 **개인 정답률·평균 반응시간 즉시 표시**.
- 문항별 정답 및 결과는 교수의 별도 공개 버튼으로 공개됩니다.

## 교수용
- 분반 선택 후 비밀번호 입장.
- 12주차 또는 13주차 실습을 선택하여 열기/닫기.
- 제출 완료 수, 등록 인원, 정답률/반응시간의 전체 평균, 개별 결과, 분포 및 문항별 통계.
- CSV 내려받기, 문항별 정답/해설 공개 및 닫기.

## 최초 배포
1. 기존 Supabase 프로젝트 SQL Editor에서 **`schema.sql` 실행**.
2. 새 GitHub 저장소에 `app.py`, `frontend/index.html`, `requirements.txt`, `.gitignore` 업로드.
3. Streamlit Cloud에서 이 저장소의 `app.py`를 지정.
4. Streamlit Cloud → App settings → Secrets에 `SUPABASE_URL`, `SUPABASE_KEY` (**service_role 키**, 서버에서만 사용), `PROF_PASSWORD` 등록.
5. **데이터베이스에는 RLS가 활성화되어 있어야 하며, 학생 측 JS에는 Supabase 키를 넣지 않습니다.**
6. 교수로 접속 → 수업 분반 열기 → 학생 두 명으로 각각의 테스트를 끝까지 시범 실행 → 교수 집계와 저장 여부 확인.

## 유지되는 원본 구조와 차이
- RPM: 이전 코드의 원본 `ITEMS` 배열, 도형 생성 함수/정답을 그대로 가져왔습니다.
- 하트/꽃: 원래 코드의 20회/독립 무작위/왼쪽·오른쪽/하트 같은쪽·꽃 반대쪽 규칙을 유지합니다.
- 기존 Google Sheets 자동 전송 및 로컬 CSV 저장 버튼은 제거했습니다. 대신 Supabase에 완료 단위로 저장하며 교수 화면에서 CSV를 다운로드합니다.
- 휴대전화의 긴 실습 중 페이지 새로고침 시 **진행 중인 미완료 데이터는 사라집니다.** 완료 후에는 학생별 한 회 결과를 보존하며 중복 제출을 방지합니다.
- 동일 학생 이름을 다른 사람이 입력하면 결과를 볼 수 있으므로, 필요하면 이름 대신 수업용 별명을 정하고 비밀로 유지하십시오. 이는 고위험 평가용 인증 시스템이 아닙니다.
- 이 활동은 정식 RPM 표준검사나 빈곤의 인지적 효과에 대한 인과실험이 아닙니다.

## 점검 사항
- 새 앱의 화면·코드 정적 검사는 가능하지만, 실제 Streamlit Cloud·Supabase 접속 및 모바일 기기별 지연 측정은 **배포 환경에서 별도 확인**이 필요합니다.
- 테이블명은 `scarcity_lab_*`를 사용하며 BQ(retire)에는 영향을 주지 않습니다.
